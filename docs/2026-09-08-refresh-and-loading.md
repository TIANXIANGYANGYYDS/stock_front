# 刷新、K 线与股票搜索优化

## 排查结果

当前源码没有三分钟整页重载的定时器或 `location.reload`。日期查询每 60 秒执行，价格快照每 5 秒执行，分钟 K 每 30 秒执行。

确认的闪烁路径是：日期接口在已有有效日期后返回空值会卸载工作区；日线加载状态会隐藏已有数据并销毁图表，刷新失败也会清空已有日线。此外，整个工作区原先套有透明度入场动画，顶部指数的轮询状态位于 App，会让整个工作区参与 React 更新。React 更新本身不等于浏览器重新加载页面。

2026-09-08 经本地 `/backend-api` 代理访问实际后端的抽样：日线 120 条约 165 毫秒、约 298 KB；活跃股票池约 260 毫秒、约 225 KB；代码和名称搜索并发时各约 6.2 秒，后续顺序请求约 3.3–3.6 秒。该测量不能进一步区分后端查询、连接池排队与服务端缓存的耗时，但搜索瓶颈发生在接口响应之前。

## 修改

- 顶部指数轮询移入独立组件；移除整个工作区的透明度入场动画。日期轮询短暂返回空值时继续使用上次有效交易日，首次加载仍等待有效日期。
- 同一股票日线更新和请求失败时保留已有图表、指标与历史查看位置，显示更新或错误提示；切换股票仍校验代码，避免显示上一只股票的数据。
- 日线、分钟线和指标先比较数据。相同数据不写入图表，末尾修改或追加用 `series.update`；历史修正、窗口滚动或点位删除才调用 `setData`。保留已打开的图表实例及查看区间。
- 搜索结果、活跃股票池和日线使用 60 秒内存缓存，分别最多保留 60 个列表和 24 份日线。缓存键包含交易日和查询条件，过期后重新请求。实时价格和分钟 K 的轮询不使用这层缓存。
- 并发相同查询共享网络请求。一个调用方取消不影响其他调用方；所有调用方取消后中止请求，不缓存失败或取消后的晚到响应。
- 股票导航和指令中心共享搜索缓存。首次加载、清空搜索、命中缓存时不再额外等待输入防抖；新的输入保留 180 毫秒防抖。
- 股票行悬停或键盘聚焦 120 毫秒后预加载日线；点击复用该请求，离开时释放预加载。聚焦同一行不会取消正在进行的悬停预加载。

## 验证

- `npm test -- --maxWorkers=4`：52 个测试文件、381 个测试全部通过；`npm run build`、项目类型检查和以 `App.tsx` 为入口的完整前端严格类型检查通过。
- 单元与组件回归覆盖缓存过期/容量/取消、日线末尾更新和历史修正、刷新失败保留行情、悬停转点击、连续三次日期轮询不卸载工作区。
- 浏览器使用真实搜索和日线接口：首次名称搜索约 3.8–4.6 秒；同一查询在缓存期内再次搜索约 48–50 毫秒，新增搜索请求为 0。预加载后点击的新增日线请求为 0。
- 浏览器推进三轮各 61 秒的时钟，并将日期接口临时返回空值：工作区和图表 canvas 均保持同一 DOM，工作区透明度始终为 1，导航仅首次打开一次，没有运行时异常。
- 这些数字是本地抽样，并非线上性能保证。首次未缓存的搜索仍受后端影响；进一步优化需在后端记录接口分段耗时并检查股票检索查询计划。

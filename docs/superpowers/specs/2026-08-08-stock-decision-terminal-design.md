# 综合股票决策终端设计规格

日期：2026-08-08

## 1. 目标

将现有“新闻资讯仪表盘”改造为综合股票决策终端。终端必须以真实股票数据驱动的专业蜡烛图为核心，同时完整承载盘前主线、板块热度、投资倾向、个股 AI 分析和实时资讯。

本次只使用后端已经提供的数据，不为缺失行情制造模拟值。当前后端契约包含：

- `GET /api/v1/market/indices`
- `GET /api/v1/news/recent`
- `GET /api/v1/morning-analysis`
- `GET /api/v1/rankings/investment-preference`
- `GET /api/v1/rankings/market-heat`
- `GET /api/v1/sector-stock-analysis`

## 2. 设计依据

东方财富的行情页把周期切换、K 线缩放、全屏、均线和技术指标放在图表工具栏，并把 OHLC、成交量、换手率和阶段涨幅等数据放在图表周围。参考：<https://quote.eastmoney.com/zs000001.html>。

同花顺行情中心使用高密度表格展示现价、涨跌幅、涨速、换手率、量比、振幅、成交额、市值和市盈率，说明专业行情界面需要更紧凑的信息层级。参考：<https://q.10jqka.com.cn/>。

蜡烛图使用 Lightweight Charts 5.x。它提供 Candlestick、Histogram、Line、Crosshair、Price Line 和时间轴缩放等金融图表能力。参考：<https://tradingview.github.io/lightweight-charts/docs/5.0>。

本项目吸收这些交互习惯，但不复制竞品视觉资产或品牌样式。

## 3. 信息架构

应用使用单一专业终端外壳，顶部提供三个主视图：

1. **决策台**：默认首页，以蜡烛图和 AI 决策为核心。
2. **市场洞察**：盘前分析、主线板块、投资倾向和市场热度。
3. **实时资讯**：新闻流、情绪筛选和详情阅读。

顶部固定区域还包含品牌、市场日期、数据状态，以及五个主要指数。桌面端优先适配 1280–1920 像素宽度；窄屏自动改为可滚动的单列布局。

## 4. 决策台

### 4.1 左栏：机会雷达

左栏宽约 280 像素，负责从板块收敛到个股：

- “投资倾向”和“市场热度”两个榜单标签。
- 每个板块显示排名、分数、变化和新闻数。
- 点击板块后请求 `sector-stock-analysis`。
- 板块下方显示该板块个股列表、涨跌幅和 AI 建议。
- 首次加载时自动选择第一个有效板块和第一只有 K 线的股票。

### 4.2 中栏：行情图表

中栏占据最大可用宽度，分为股票摘要、图表工具栏和图表主体：

- 股票摘要：名称、代码、最新价、涨跌额、涨跌幅、日期。
- OHLC 条：随十字光标显示当前蜡烛的开、高、低、收；无悬浮时显示最新一根。
- 图表：A 股红涨绿跌的蜡烛、右侧价格轴、底部日期轴、网格和最新价线。
- 均线：MA5、MA10、MA20，图例颜色固定且可切换显示。
- 成交量：独立下方 pane，柱色与对应蜡烛一致。
- 交易计划：买入、止损、止盈使用有标签的水平价格线。
- 工具栏：近 10/20/30 根、均线开关、成交量开关、适配内容、全屏。
- 数据校验：过滤日期或 OHLC 非法的蜡烛，排序并去重；无有效数据时显示空状态。

后端当前仅返回约 30 根日 K，因此不伪造分钟、周、月周期入口。将来增加对应 API 后再扩展周期切换。

### 4.3 右栏：AI 决策

右栏宽约 330 像素：

- 清晰展示“买入 / 观察 / 回避”状态和分析状态。
- 展示计划买入、止损、止盈三个关键价位。
- 展示触发条件、预期入场方式、结论和详细原因。
- 展示最新行情指标：振幅、换手率、成交额、开高低收。
- 所有结论标注“仅供研究参考”。

## 5. 市场洞察

市场洞察保留现有业务能力，但统一到新的视觉系统：

- 盘前主线：分析日期、主线优先级、理由和关联个股买入统计。
- 投资倾向：榜单和 10 日趋势。
- 市场热度：热度榜、新闻数量和趋势。
- 点击任意板块可直接进入决策台，并触发该板块个股分析。

## 6. 实时资讯

资讯页使用列表 + 详情双栏结构：

- 搜索标题、正文、股票和板块。
- 按全部、利好、中性、利空筛选。
- 按时间或影响评分排序。
- 列表展示来源、时间、分数和关联板块。
- 详情展示正文、LLM 分析原因、关键要点、关联股票和板块。
- 点击关联板块可跳转到决策台。

## 7. 视觉系统

- 背景：深海军蓝黑，不使用纯黑。
- 面板：低对比度层级，通过边框、间距和局部高光区分，不使用大面积玻璃模糊。
- 主强调色：冷青蓝，用于选中、链接和交互状态。
- 行情色：红色上涨、绿色下跌，符合 A 股习惯。
- 均线色：MA5 金黄、MA10 紫色、MA20 青色。
- 字体：系统中文字体栈；数字使用等宽数字特性。
- 密度：桌面专业终端采用 12–13 像素辅助文字、14–16 像素正文，关键价格 22–28 像素。

## 8. 前端架构

应用按职责拆分：

- `AppShell`：顶部导航、指数带和视图切换。
- `DecisionWorkspace`：板块、个股和选中状态编排。
- `OpportunityRadar`：板块与个股列表。
- `ProfessionalCandlestickChart`：图表实例、数据转换、均线、成交量和价格线。
- `DecisionPanel`：AI 决策与行情摘要。
- `MarketInsightsView`：现有市场分析组件的统一容器。
- `NewsIntelligenceView`：资讯查询、筛选和详情。
- `chart-data`：纯函数负责 K 线清洗、排序、去重和均线计算。
- `api`：继续作为后端适配边界，扩展 K 线字段并保持 UI 不依赖原始 snake_case。

不引入全局状态库；选中视图、板块和个股由应用工作区状态管理。现有规模下 React 本地状态足够。

## 9. 数据流与错误处理

- 首屏并行请求指数、投资倾向、市场热度、盘前分析和资讯。
- 不同区域独立展示加载、错误和空状态，单个接口失败不应使整个应用白屏。
- 板块切换时取消过期请求结果，避免快速点击造成数据错配。
- API 基础地址通过 `VITE_API_BASE_URL` 配置；Vite 代理目标通过环境变量配置。
- 当前代码中的固定代理地址已指向无关服务，因此生产联调必须提供新的股票后端部署地址。
- 删除演示指数和个股回退数据；数据不可用时明确显示“数据暂不可用”。

## 10. 测试与验收

自动化验证至少包含：

- K 线非法数据过滤、日期排序和日期去重。
- MA5/MA10/MA20 计算。
- API K 线字段映射，包括成交额与涨跌字段。
- TypeScript/Vite 生产构建。

人工验收：

- 1280、1440、1920 像素桌面宽度布局稳定。
- 点击板块会加载个股，点击个股会同步更新图表和右侧决策。
- 十字光标、缩放、拖动、均线、成交量和价格线正常。
- API 失败时每个区域显示可理解的错误信息，没有虚假行情。
- 市场洞察和实时资讯的功能没有因首页改造丢失。

## 11. 范围边界

本轮不实现后端没有支持的数据：分钟 K、周 K、月 K、实时推送、任意股票搜索、盘口五档和账户交易。界面不会用静态模拟数据假装这些能力存在；后续新增 API 后可在既有组件边界内扩展。

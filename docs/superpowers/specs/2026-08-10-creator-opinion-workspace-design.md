# 博主观点工作区设计

## 目标

在现有“决策工作台、市场洞察、实时资讯”之外新增独立的第四个一级工作区“博主观点”，完整接入 Stock_Project 已提供的博主账号、作品、观点分析和准确率汇总接口。页面必须同时满足观点浏览、博主评分排行、作品详情阅读和历史验证解释四个核心需求。

所有观点、评分和验证结论均来自后端真实字段。前端只负责字段适配、展示排序和有效样本计数，不重新计算准确率，不推导交易建议，也不补造缺失正文、评分或验证结果。

## 非目标

- 不在前端创建、编辑或验证博主观点。
- 不根据观点自动生成买卖建议或推荐股票。
- 不把无评分博主显示成 0 分。
- 不一次性加载全部历史作品。
- 不在本阶段嵌入或代理第三方视频播放器；作品通过原始链接打开。
- 不改动现有三个工作区的数据逻辑和视觉职责。

## 后端接口

工作区接入以下只读接口：

- `GET /api/v1/creator-accounts`
- `GET /api/v1/creator-accounts/{account_key}`
- `GET /api/v1/creator-works`
- `GET /api/v1/creator-works/{work_key}`
- `GET /api/v1/creator-opinion-analyses`
- `GET /api/v1/creator-opinion-analyses/{creator_id}`

作品列表默认携带 `is_a_share_relevant=true` 和 `status=finished`。分页、博主、平台、关键词、开始时间和结束时间优先交给后端处理；作品内嵌观点的方向筛选在当前已加载结果中完成。

博主观点属于持续更新的实时内容，可以在周末或收盘后产生，因此不使用股票最新交易日截断。24 小时、3 天和 7 天筛选均以浏览器当前北京时间生成请求范围；“全部”不发送时间范围。

## 前端数据模型

`src/app/lib/api.ts` 继续作为 Stock_Project 的反腐层，新增以下稳定的 UI 类型：

- `CreatorAccount`：博主 ID、显示名称、平台、账号键、主页地址、认证状态和备注。
- `CreatorOpinion`：观点 ID、标的范围和类型、标的名称、方向、立场强度、观点正文、期限、有效期、指标、条件、置信度、可验证性、原始引用和验证日期。
- `CreatorWorkSummary`：作品键、博主、平台、发布时间、标题、内容类型、A 股相关性、处理状态和列表内观点。列表接口不返回完整 AI 分析。
- `CreatorWorkDetail`：列表字段加完整 AI 分析、正文、提取文本、ASR、OCR、媒体地址和原始作品地址。
- `VerifiedCreatorOpinion`：观点、发布时间、方向、标的、验证日期、验证时间、验证结论、实际分值和评分理由。
- `CreatorOpinionAnalysis`：博主 ID、博主名称、后端准确率、已验证观点和待验证观点。
- `CreatorWorkResponse`：作品列表、分页信息和当前筛选上下文。

新增 API 函数：

- `getCreatorAccounts()`
- `getCreatorWorks(filters)`
- `getCreatorWorkDetail(workKey)`
- `getCreatorOpinionAnalyses()`
- `getCreatorOpinionAnalysis(creatorId)`

字段适配必须容忍后端未知平台、未知方向、未知验证状态、缺失数组和空数值，不能因为单条脏数据中断整个页面。

## 信息架构

`WorkspaceView` 增加 `creators`，顶部主导航新增“博主观点”。工作区标题下显示四项实时概览：监控博主数、A 股相关作品数、已获得准确率的博主数、等待验证观点数。

桌面主体采用三栏布局：

1. 左栏“博主评分排行”：博主排名、准确率、有效评分样本数、待验证数和样本提示。
2. 中栏“最新观点流”：作品卡片、搜索和筛选、分页加载。
3. 右栏“作品与观点详情”：完整作品信息、AI 摘要、逐条观点、验证结果和原始内容。

页面顶部筛选栏包含关键词、24 小时/3 天/7 天/全部、平台、观点方向和清除筛选。选中博主同时作为作品筛选条件显示在筛选摘要中。

## 博主评分排行

排行使用后端 `accuracy_score`，前端不重新计算准确率。排序规则为：

1. 有准确率的博主排在前面。
2. 准确率从高到低排列。
3. 准确率相同时，有效评分样本更多者靠前。
4. 没有准确率的博主放入“数据积累中”区域，不显示数字名次。

有效评分样本仅统计 `score` 为有限数字的已验证观点。准确率存在但有效样本少于 5 条时显示“样本较少”。每个排行项同时显示有效样本数和待验证数，避免将少量样本的高分解释成稳定预测能力。

点击博主后：

- 中间作品流只显示该博主。
- 右栏顶部显示该博主的准确率和验证结构。
- 当前作品不属于该博主时清空作品选择。
- 再次点击当前博主取消筛选。

## 最新观点流

作品流按发布时间倒序展示，每张卡片包含：

- 博主名称、平台和发布时间。
- 作品标题与首条观点正文预览；列表阶段不显示尚未请求到的 AI 摘要。
- 作品中观点数量。
- 前几条观点的方向、标的名称和立场强度标签。
- 可验证观点与长期/不可量化观点的数量提示。

方向使用文字、图标和颜色共同表达：看多为红色、看空为绿色、中性为灰蓝色。未知方向采用中性样式并展示原始值。

列表使用固定页大小和“加载更多”。改变博主、关键词、时间或平台筛选时回到第一页并清空旧列表；加载更多时追加并按 `work_key` 去重。方向筛选作用于当前已加载作品，筛选摘要明确显示结果数量。

选择作品后请求详情接口。切换列表筛选导致所选作品不再可见时，选择新结果第一条；没有结果时清空右栏。

## 作品与观点详情

详情顶部显示标题、博主、平台、发布时间、内容类型和“查看原始内容”链接。外部链接使用新窗口和安全的 `rel` 属性。

详情提供“观点分析”和“原始内容”两个页签：

### 观点分析

- 首先显示后端 AI 摘要。
- 逐条显示观点方向、标的类型、标的名称、立场强度、置信度、期限、有效期、衡量指标、成立条件、验证日期和原始引用。
- `verifiable=false` 显示“长期/不可量化观点”，不进入等待评分语义。
- 将同一 `opinion_id` 的验证记录合并到观点卡片中。
- 已验证观点显示结论、实际分值、验证时间和完整评分理由。

验证状态中文映射：

- `corroborated`：命中。
- `partially_corroborated`：部分命中。
- `contradicted`：观点相反。
- `not_triggered`：条件未触发。
- `unverified`：证据不足。
- 无结论且存在验证日期：等待验证。
- 未知状态：待识别状态，并保留后端原始值。

### 原始内容

正文展示优先级为 `source_text → extracted_text → asr_text → ocr_text`。界面标明当前文本来源；所有字段为空时显示“暂无可读原文”。长文本在详情栏内滚动，不扩张整个页面。

## 数据流与状态隔离

进入工作区时并行加载博主账号、评分排行和第一页作品。三个请求具有独立的 loading、error 和 retry 状态：

- 评分失败不阻止作品浏览。
- 作品失败不清空已经成功加载的评分榜。
- 详情失败只影响右栏，并保留当前列表和选择。
- 账号接口失败时使用分析和作品中的博主名称继续工作，只隐藏账号主页与认证信息。

组件卸载、筛选变化或连续选择作品时忽略过期响应，防止慢请求覆盖新选择。详情按 `work_key` 在当前页面会话中缓存，重复选择不重新请求。

## 组件边界

- `CreatorInsightsView.tsx`：工作区状态、初始并行请求、筛选和选择协调。
- `CreatorRankingPanel.tsx`：排名与博主选择，只接收映射后的排行项。
- `CreatorWorkStream.tsx`：筛选摘要、作品列表和加载更多。
- `CreatorWorkDetail.tsx`：作品详情、观点与原始内容页签。
- `creator-opinion-state.ts`：排行排序、有效样本计数、状态映射、作品过滤、文本来源选择和观点验证合并等纯函数。

每个组件只依赖明确 props，不直接解析后端原始字段。所有 Mongo 字段差异集中在 `api.ts`。

## 空状态与错误状态

- 初始加载使用与终端视觉一致的骨架屏。
- 空排行显示“暂无可评分博主”，作品流仍可使用。
- 空作品显示当前筛选条件、结果数量和“清除筛选”按钮。
- 列表错误显示后端错误文本和“重新加载”。
- 详情错误显示右栏局部错误和“重新加载详情”。
- 空准确率显示“数据积累中”，不能回退为 0。
- 缺少账号主页时不渲染无效链接。
- 列表预览优先使用首条观点正文；没有观点时使用作品标题，二者都缺失时显示“暂无观点预览”。作品 AI 摘要只在详情请求成功后展示。

## 响应式与可访问性

- 宽屏使用三栏，建议列宽为约 `300px minmax(440px, 1fr) 440px`。
- 中等宽度使用评分榜和观点流双栏，详情以右侧滑层打开。
- 手机使用“排行 / 观点”页内切换，详情全屏打开。
- 所有排行项和作品卡使用真实按钮语义，支持键盘操作和清晰焦点。
- 选中状态使用 `aria-pressed` 或 `aria-current` 表达。
- 方向和验证结果不能只依赖颜色，必须同时显示文字和图标。
- 长标题、原文和评分理由具有可滚动区域，不能造成横向溢出。

## 测试策略

纯函数和 API 测试覆盖：

- 原始账号、作品、观点和分析字段映射。
- 缺失数组、未知枚举和空准确率处理。
- 准确率排序、有效评分样本统计和少样本提示。
- 验证状态中文映射与实际分值保留。
- 观点和验证记录按 `opinion_id` 合并。
- 正文来源选择优先级。
- 方向筛选和作品追加去重。
- 所有路径参数正确进行 URL 编码。

组件测试覆盖：

- 顶部第四个导航可进入博主观点工作区。
- 初始排行、作品和详情正常渲染。
- 点击博主筛选作品，再次点击取消。
- 切换筛选重置分页和旧选择。
- 加载更多追加并去重。
- 作品详情按需请求并使用缓存。
- 空准确率不显示为 0 分。
- 排行、列表和详情错误互不阻塞。
- 空数据、重试、原始内容切换和外部链接语义正确。

最终验证运行完整 `npm test` 和 `npm run build`，并在真实 Stock_Project 接口下检查桌面三栏、中等宽度详情滑层和手机单栏布局。

## 完成标准

- 主导航出现可访问的“博主观点”入口。
- 页面可浏览真实 A 股相关博主作品和完整观点内容。
- 页面可查看后端准确率排行、有效样本数和待验证数。
- 作品观点与验证结果能够按 `opinion_id` 对应展示。
- 少样本、空评分、不可验证观点和证据不足不会被误导性展示。
- 现有三个工作区行为不回归。
- 新增测试、完整测试和生产构建全部通过。

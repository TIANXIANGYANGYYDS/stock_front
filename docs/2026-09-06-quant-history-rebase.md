# 连续账户历史补录适配

本次保留现有量化页面、Radix 详情、Recharts 曲线与业务列表，适配后端连续账户重算。策略身份继续使用目录公开名称；指标、参数、原因、确认和执行过程保持可读。

## 契约与日期来源

指定的三份 Linux 交付文件在当前 Windows 工作区不可访问。已通过项目现有 `/backend-api` 代理读取已配置后端 `/openapi.json`，并核对策略目录、总览、收益历史与所有日期明细的真实响应。沿用 API base URL、环境变量和端口 8100 的现有代理配置。

删除生产代码中的固定记录起点和截止日期。账户起点读取 `overview.data.recording.start_date`，最新已有交易日读取无日期参数的 `overview.data.trade_date`。完整读取 `performance` 的所有分页，按交易日升序供日期选择器与曲线共用，不生成缺失日期。

当前日期选择器只列出已返回的实际交易日。所选日期的账户总览、列表和完整日记录同步切换，明细重置到第一页。账户头部显示所选日期的“数据截至日期”和“账户统计区间”；收益曲线默认保持从账户起点至最新已有交易日的完整区间，并独立标注其截至日期。成交和平仓标签仍为所选交易日。

## 缓存与快照处理

- 检查确认：量化业务响应未写入 localStorage、sessionStorage、IndexedDB、Service Worker 缓存。现有 `useWorkspaceState` 仅在内存中保存界面选择，量化日期与筛选已使用新命名空间；未清除其他模块或主题设置。
- 总览、历史、日期选项和明细均由本次请求生成。历史整体替换，不与旧数组拼接；schema 和 runtime 版本相同也不会阻止新快照更新。
- 明细请求键保留策略、交易日、快照、筛选、页码和每页数量。历史上下文改变后重新加载所选日期总览，核对它与 performance 对应交易日的 snapshot_id，再展示该日期明细。
- 409 由最新总览统一恢复，清理历史与分页；自动恢复最多一次。持续冲突暂停并提示手动刷新。请求失败不显示虚假零资产、无持仓或无交易。
- 普通页面只有最新总览的一分钟轮询。查看历史日期时也能发现新交易日；所选历史日期保持不变。完整日记录仍按需加载，不重复轮询下载全部账本。
- 源码与当前构建入口检查未发现固定的本次日期范围、账户数、资产、盈亏核验值或测试样本导入。

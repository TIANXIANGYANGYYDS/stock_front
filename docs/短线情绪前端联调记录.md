## 服务端保留机制 v1.2 适配（2026-10-15，当前实现）

已同步提供的接口说明、OpenAPI v1.2 和响应示例，并经项目现有 `/backend-api` 代理核对运行中 `/openapi.json`、REST 响应及浏览器 SSE。以下实现取代后文早期的浏览器内存保留、分钟统计兜底和连续跨缺口连线方案。

- 直接使用服务端完整保留发布，不再把缓存中的旧总览、成员和分钟统计拼入新快照。支持 `is_retained / retention_reason / retained_from_snapshot_id / processed_as_of / finalization` 及 `retained_observation`。保留来源 ID 仅溯源，关联查询始终绑定当前发布 ID。
- 页面及详情显示真实 `as_of`、保留原因、观察年龄、覆盖和待定稿原因；未知原因保留原文。顶层 `is_stale=true` 不清空仍可回看的个股。时间按上海时区显示，不叠加时钟校准偏移，不凭浏览器时间宣布定稿。
- 默认前七直接请求 `/themes/{id}?page=1&page_size=7&sort=board_strength`，保持服务端顺序，不先筛掉 ST、未触板或缺行情成员。图例和完整成员行标记排除/缺失状态，统计始终读取后端。显式股票、板块或状态筛选时读取全部分页，再按原顺序筛选；详情支持完整成员分页。
- 题材卡中的统计、排行和观察时间来自同一次题材响应。新版本请求期间保持整组旧响应并标注正在同步，不将新统计与旧排行拼接。快照更新串行合并；成员查询 409 向工作区请求一次总览重同步，并发重同步复用在途请求，不反复请求旧编号。范围、日期、题材变化取消旧请求，迟到版本不覆盖新选择。
- 收盘后持续接收 SSE；新发布编号或同编号定稿状态变化都会刷新成员、统计历史、详情和归档/事件读取。心跳只更新元数据。历史日期不连接 SSE，刷新/首次进入均从服务端恢复。
- 分钟走势绑定发布快照，但读取返回的所有真实点，不按保留 `as_of` 截断。秒级图继续复用单股真实归档接口，保留期查询至 `processed_as_of`，排行时间仍标为 `as_of`。空值、明确无效采样和时间缺口断开；不补价格，不用总览倒填历史。正式日级事实与分钟采样分开，定稿不补齐分钟缺口。

## 收盘待定稿期间的展示保护（2026-10-15）

真实接口核验：`all_a:2026-10-15:00003410` 的 `as_of=15:04:58`、`session=closed_pending_final`、`is_final=false`、覆盖为 0；市场统计为 null，成员标记 `stale_source_time`，有效性及价格被清空。分钟接口仍有 14:56:03 的有效统计：覆盖约 99.24%，涨停 36、跌停 28、最高 5 板。携带该分钟对应的旧快照查询总览返回 409，不能通过旧 ID 重新获取完整排行。因此不能把当前空快照解释成收盘没有涨停，也不能把 14:56 的观测冒充最终收盘结果。

- 收盘竞价或收盘待定稿期间，若新快照统计失效，保留同范围、交易日、分类及规则版本下已经加载的有效观察；最新查询仍绑定后端当前快照，避免拿旧 ID 发起关联查询。
- 已加载题材的有效成员因收盘失效而减少时，保留此前完整成员及排行，全天曲线继续读取真实归档。关闭实时闪动，标注最后有效时间及“非最终收盘结果”；后端定稿到来后自动替换，包括快照 ID 未改变的定稿更新。
- 收盘后首次打开且没有内存缓存时，市场和当前选中题材各读取分钟接口最后有效统计。没有真实个股排行时明确显示等待收盘排行，不绘制误导性的 TOP 0 空图，不从历史统计猜测股票名单。
- 缓存仅在当前页面运行期间保留，市场最多 4 组、题材成员最多 8 组；刷新浏览器后不保证保留此前排行。跨范围、日期或版本不混用，正常交易中的真实数据故障仍明确展示。

真实页面验证：市场正确展示 14:56:03 的 36 / 28 / 5，最新空快照信息仍保留；无缓存题材明确等待收盘排行。1680 px 桌面及 390 px 移动端无运行时错误，移动端无横向溢出。情绪模块 12 个测试文件、80 项测试通过，类型检查和生产构建通过；新增覆盖收盘保留、首次进入的分钟读取、最终定稿替换、题材重开以及范围和日期隔离。

后端仍需修复：非交易时段的无效采样不应覆盖最后有效快照；等待定稿时应能读取实际保留的成员及排行，最终收盘数据发布后再更新。前端保护不代表后端已经修复，也不补造任何行情。

## 秒级加载调度优化（2026-10-15）

- 原来两个任务分别占用到整只股票的全天历史读取结束，其他股票排队。改为七只股票逐段轮转，共享四个行情时间片请求槽；单股每次一段，FIFO 排队，不提高原有行情并发上限。
- 事件分页使用独立的两个请求槽，与曲线读取同时进行。收到可匹配的真实报价后即显示行为标注，不等待整日走势完成。
- 排名变化时保留仍在前七的股票订阅，只取消移出名单的请求；范围、日期、隐藏及卸载继续释放失效订阅。已完成时间片仍复用缓存，后续按真实观察游标续读。
- 合并后的同一批数据复用结果，事件更新复用报价点；图表将短时间内的通知合并到 100 ms，再按动画帧更新。加载状态和事件变化不重复构建所有曲线点。新增“已获取 X / 7 只走势 · 全天历史加载中 Y / 7”区分开始显示和完整读取。
- 收盘竞价接口在数据观察时钟达到 14:57 后才读取，避免最后一个时间片开始于 14:45 时提前请求尚未产生的竞价数据。

真实服务采样：第一次优化后，实时消费题材七条曲线约 6.9 秒开始显示，全天读取约 49 秒；完整读取时间尚受上百次旧接口请求限制。最终固定 2026-10-14 历史消费题材核验，第一批曲线及事件标注约 5.4 秒出现，七条曲线约 7.0 秒出现，完整读取约 48.1 秒，共 126 次行情请求、解码正文约 26.7 MB；无页面运行时错误，午间/收盘数据和行为提示正常。各轮截止时刻或交易日不同，这些是实测样本，不是严格控制变量的性能基准。

收盘期间另一次实时采样遇到后端可用成员持续变化、最终覆盖为零，未将该轮当作七股完整加载的对照，也未填充缺失行情。后端需要进一步提供精简的批量全天与增量曲线接口，需求已整理到 `docs/秒级叠加图后端优化提示词.txt`。

本轮验证：66 个测试文件、485 项通过；类型检查、生产构建和补丁空白检查通过。新增覆盖七股公平调度、四请求上限、排队取消、慢事件不阻塞报价、保留成员请求不中断、范围/日期清理、StrictMode 订阅释放与收盘竞价时钟。

## 已接入

- 6 个 REST 查询接口：总览、梯队、题材详情、个股详情、事件分页、分钟/日级历史。
- SSE 命名事件 `snapshot / resync / update / heartbeat / unavailable`。通过现有 API 请求封装发起 fetch 流式请求，复用基地址、代理及请求头；不增加另一套服务地址或鉴权配置。
- 全量集合替换、按代码增删、完整总览更新、心跳时效更新、独立事件 ID 去重。同一个快照 ID 补发的事件不会被忽略。
- SSE 断开后约 5 秒轮询；轮询与流式连接不会同时工作，三轮轮询后尝试重连。`Last-Event-ID` 只使用 SSE 消息 ID，事件分页只使用后端返回的游标。
- 关联 REST 请求先读总览，再携带交易日和快照 ID；409 重取整批一次。最新日期启动时若仍冲突，可通过 SSE 全量快照恢复同批数据，不继续循环 REST。404/422 不自动重试相同请求；503/网络故障退避重试。日期、筛选、分页切换和卸载会取消失效请求。
- 历史日期关闭 SSE，切换日期重置事件游标。最新交易日取自情绪总览，不依赖其他页面的最新交易日解析。

## 数据展示

- 市场、题材统计及五个昨日群体反馈直接读取后端，不由观察股票子集重新计算。
- 市场及题材的分钟统计曲线连续连接接口返回的有效点，跨越午休和空值；保留真实时间与原始空值，不插入补算数据，悬浮提示只展示实际观测值。
- `null` 显示“—”，缺失原因保留；最高板为 null 时不根据梯队猜测最高高度。

- 情绪同时解释 `status/state/candidate_state`，候选、数据不足与确认态分别展示。依据只格式化后端给出的字段，不添加评分、预测或交易信号。
- 页面显示数据所属日、截止时间、年龄、过期标志、覆盖及定稿状态。实时连接已建立并不代表行情新鲜。

- 题材详情保留被排除或行情无效的成员，提供成员分页；事件保留来源时间与观察时间。

## 个股叠加图的接口边界

`/sentiment/timeseries` 是市场或题材统计。题材七股叠加图现复用单股秒级图的 `/stocks/{code}/snapshots` 和收盘 `/auctions` 归档接口，按最多 15 分钟的请求区间读取全天数据。

默认显示 09:30 至 15:00，支持全天、上午、下午切换，压缩午休时间。使用真实采集时间与价格/昨收计算涨幅，沿用单股秒级图的有效性筛选；不制造每秒报价。已有归档的历史日期和收盘日期也可以显示全天路径。

同一范围、交易日和股票跨题材共用历史缓存；仅可见的当前题材读取，各股票按时间片轮转，最多并发四个行情时间片。已完成时段缓存，快照推进时增量读取。日期切换、离开视口和页面隐藏会取消不再使用的请求，原始空值与截断状态不会被补值掩盖。

个股事件通过 `/sentiment/events` 分页读取并按事件 ID 去重，只在存在相同来源时间的真实报价时绘制标注；无法匹配的事件仍可在详情事件列表查看。全部操作为读取接口，不重建或修改后端数据。
